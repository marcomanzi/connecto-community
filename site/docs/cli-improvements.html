CLI improvements

A coding CLI can improve how it is set up for you, from what it learned of your work. Connecto starts it on that task in a terminal you watch, and it asks you whenever it is in doubt and before anything risky.

Open Settings → CLI improvements. What it offers depends on the CLIs installed on this machine. An item that needs a CLI you do not have is not shown. Install the CLI in Settings → Agents and it appears.

Claude auto apply insights

Shown only when Claude Code is installed. Claude auto apply insights opens a new Claude Code terminal named claude-insights, on Opus, in the project you have open, and shows it. Settings closes so you can follow it. It is not offered, and says why, while a paired machine's project is shown (that machine's Claude set-up is its own), or when Claude Code is deactivated in Settings → Agents or turned off in the project's settings. The terminal:

  1. Finds the Claude config folder it runs on. That is ~/.claude, or, when the project's Claude config is Isolated, the separate one Connecto keeps for it ($CLAUDE_CONFIG_DIR). It tells you before changing an isolated one, since a change there applies to that project's Connecto terminals only.
  2. Makes a fresh insights report. It runs claude -p "/insights", Claude Code's own command that reads your past sessions and writes a report in that config folder (usage-data/report.html, or the path it prints). This can take several minutes. If it does not work, the terminal asks you to type /insights in it, and goes on when you say it is done.
  3. Reads the report and lists each concrete suggestion: settings, permissions, hooks, CLAUDE.md instructions, skills, commands, agents, MCP servers.
  4. Applies them where they belong. What is about you and all your projects goes to your user-level set-up in that config folder (settings.json, CLAUDE.md, skills). What is about the project goes in the project (CLAUDE.md, .claude/settings.json, .claude/skills). It reads a file before changing it, keeps what is there, and makes small changes.
  5. Asks you first, and waits, when a suggestion is unclear, and before anything risky: more permissions, a hook that runs commands, deleting or rewriting what is there, another project, installing anything, or anything that reaches the network. A suggestion about your habits rather than your set-up is told to you, not applied.
  6. Ends with a summary of what changed and where, and what it skipped and why.

Why the project you have open. /insights looks at your work in every project, and most of what it suggests is user-level. But a Connecto terminal belongs to a project, and the project you are working in is the one whose own set-up the suggestions can improve. Open a project first: without one the item is shown but cannot be used.

The terminal is an ordinary Claude terminal: Pause stops it like any other, and you can type into it, answer its questions, or close it.
