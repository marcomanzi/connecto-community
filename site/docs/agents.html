Agents using other terminals

Every terminal has a connecto command. With it, an agent can see the other terminals in the project, ask them things, and be told when they answer.

You do not have to teach it to them. Each agent is told about the command when its terminal starts, so you can simply write: "open a Codex terminal and have it review this diff".

The commands

CommandWhat it does
connecto listThe terminals in this project and what each is doing.
connecto send <id> 'message'Types a message into another terminal. With no message after the id, it is read from standard input.
connecto send <id> --askAsks a question. Prints a request id; the answer is delivered to the asking agent when the other one finishes.
connecto result <request>Just the final reply to a request.
connecto read <id>Everything on that terminal's screen and scrollback.
connecto keys <id> <key>…Presses keys there, for example esc down enter.
connecto tasks <id> [--stop [task]]The background work that terminal's agent left running, and for how long. --stop stops its background shells, or only the task named.
connecto watch <id>
connecto unwatch <id>		Be woken on every event in that terminal: it began, finished, was interrupted, needs the user, or exited.
connecto add claude|codex|pi|antigravity|opencode|shell [--name <text>] [--model <model>] [--effort <level>]Opens a new terminal, as a child of this one. --model picks the agent's model; for Pi and OpenCode it is provider/model, such as openrouter/<id> or lmstudio/<id>. --effort picks its reasoning effort, in the agent's own words (low, medium, high…). Both are kept with the terminal, so a restart uses them too.
connecto start <id>Starts a terminal that is not running.
connecto close <id>Stops a terminal and moves it to the history.

When project memory is on for the project, the same terminals also get the connecto memory commands. They read the project's memory and leave notes for it.

Driving a shell terminal

A shell terminal is your login shell, not an agent, so it has no turns. Run a command in it with connecto send shell '<one command line>' (one line per send; use ; or && to join commands) and look at the result with connecto read shell, waiting a moment for a slow command. connecto keys shell ctrl-c interrupts it. send --ask, watch and result are refused for a shell, with a message that says to use send and read.

Asking and getting an answer

send --ask is the one that makes agents a team. The asking agent sends its question and ends its turn. It does not wait, sleep or poll. When the other agent finishes, Connecto wakes the asker with the reply already in its context, labelled as another agent's words.

connecto add codex --name "review the diff"

connecto send codex-4 --ask <<'EOF'
Review the migration in db/2031_orders.sql. Is anything unsafe
to run on a table with live writes?
EOF

The new terminal appears in the sidebar under the one that opened it, so you can watch the reviewer work and step in at any point.

Whose terminal is it

A terminal an agent opens with connecto add belongs to that agent. Only it, and the other terminals it opened, can send to it, press keys in it, start it or close it; any other agent is refused and told to open its own. Reading and watching stay open to all. connecto list marks such terminals yours or belongs to <id>. Terminals you open yourself belong to nobody and every agent can use them.

Agents working together

Terminals opened by the same agent talk to each other directly. To have two of them do something together, a review, a back-and-forth, a game, ask one of them and give it the other's id: it runs the exchange with send --ask and answers once, at the end. While it waits on its own asks, the first ask stays open, so the agent that started it is woken only when the work is done, not after every exchange.

What you should know

  • Agents do not ask you first. One agent can type into another terminal without approval. That is the point, and it is why Pause exists.
  • Pause is a full brake. While it is on, sends, keys, add, start, close and wakes are all refused, and the agent is told why. An agent cannot lift Pause.
  • There is no rate limit. Two terminals that watch each other can keep waking each other, and every wake is a model turn on your plan. Pause stops it, and so does unwatch.
  • Everything is recorded. Each agent action goes to the audit log with who did it and the text, with secrets redacted.
  • Messages are limited to 4096 bytes after redaction. A longer one is refused, not cut short.

Text on a screen can steer an agent. An agent that reads another terminal reads whatever is there, including text that came from a web page or a file. Treat the reach of one agent as the reach of all the terminals it can drive.

Exit codes

CodeMeaning
0Done.
