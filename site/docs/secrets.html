Secrets

Settings → Secrets is a vault for API keys, tokens, passwords and SSH keys. Agents can use what is in it, in ways you allow, without Connecto handing the value to the terminal: the vault gives a terminal a proxy address, filtered program output or an ssh-agent socket. An allowed program or server receives the credential and must be trusted with it.

Without the vault, the only way to give an agent a token is to put it where the agent can read it: an environment variable, a file, the prompt. From there the agent can print it, and it travels with the screen into history, memory and messages to other agents. Connecto has no sandbox (see Pause, audit and redaction), so the vault does not try to hide values from a process that holds them. It keeps them out of the terminal's processes altogether.

What never happens to a value

  • Connecto never puts it in a terminal. No environment variable, no file, no command line in the terminal's processes. No connecto command returns a value: connecto secret list gives names and uses; url, run and ssh give a proxy address, filtered program output or an ssh-agent socket, and request only an acknowledgement. An allowed program or bound server does receive the value, and must be trusted with it: one that prints or returns it in a form Connecto does not recognize reveals it to the terminal (see the limits).
  • It is hidden in the text Connecto redacts. Connecto removes every vault value from the audit log (including its copy of messages between agents), history transcripts, project memory, and the screen that connecto read returns. It looks for the exact value and for the forms a command line produces on its own: base64 (both alphabets, at every offset), hex in either case, and percent encoding.
  • It is not written to the log of uses. Uses through a terminal are recorded by the secret's name, the terminal and the target, never the value.

A message between agents is delivered as written. connecto send removes control characters and types the rest into the other terminal; it does not hide vault values. If a value has reached an agent some other way (a program that printed it in a form Connecto does not recognize, say), that agent can pass it on, and only the audit copy of the message is redacted.

A value must be at least 8 bytes long (at most 16 KB), so that hiding it never hides ordinary text.

Your own view of a terminal is not redacted: if a program prints a value, you see it. The same goes for remote viewing, which streams a terminal's raw output to your own paired Macs.

Where the vault is kept

Values are kept in Connecto's secrets document (see Where secrets are kept), each one encrypted with AES-256-GCM under a master key that is kept somewhere else:

Where Connecto runsThe master keyWhat that protects against
macOSA Keychain item (connecto / vault-key)The Keychain gives the key to Connecto without asking, and asks you before any other program reads it. An agent that copies the secrets file gets ciphertext.
WindowsA Credential Manager credential of the same nameOther users, and copies of the file. Not programs running as you, which can read your credentials.
Linux, and any build with a data folder of its ownThe file secrets/vault.key in the data folder, readable only by you (mode 600)Only a plain read of the secrets document. The key sits beside it.

Settings → Secrets says which of these is in use on this machine.

The rest is not secret and is kept in secrets/vault.json in the data folder (mode 600): each secret's name, scope, description, uses and times. Listing secrets never needs a value. The log of uses is secrets/uses.jsonl: one line for each web request, program run, ssh-agent socket and signature, by name, terminal and target. It is best effort (a line that cannot be written is skipped), and Connecto's own reads of Agentic Works credentials are not in it, so a secret missing from it is not proof that it was never used.

Each value is sealed with its own place in the store (scope and name) as associated data, so a value copied under another name does not open.

Adding, changing and removing secrets

Open Settings → Secrets. Each secret is a card with its name, where it is kept, what it is for, and how it may be used.

  1. Choose where to keep it: App-wide, or one project.
  2. Enter a name, such as GITHUB_TOKEN: a letter, then letters, digits, _ or -, at most 64 characters. Terminals see the name, so keep it plain.
  3. Optionally, say what it is for (shown to terminals in connecto secret list).
  4. Paste the value, or for an SSH key click Generate an SSH key: Connecto makes an Ed25519 pair and shows the public key to give the server.
  5. Click Add secret.

A new secret can be used by no terminal until you choose how. (One exception: Generate an SSH key on <Mac>, for a paired Mac's project, keeps the key there with the SSH use already set.) On its card, How it is used… offers:

UseWhat you setWhat a terminal can then do
Web requestsAn address (https://, or http:// to this machine only, with no user name, query or fragment), a header (Authorization by default) and what goes before the value (such as Bearer )Send requests to that address through Connecto, which adds the header
One programThe full path of each program allowed (up to 16, one per line) and an environment variable, such as GH_TOKENHave Connecto run one of those programs with the value in that variable
SSH keyNothing more: the value is an OpenSSH private key without a passphraseSign SSH logins through an ssh-agent Connecto serves, and read the public key
Agentic Works database and Google Cloud service accountProject secrets onlyNothing: only Connecto uses them. See Agentic Works.
Not usableNothing

Setting a use is the consent: there is no prompt each time a terminal uses the secret. Uses are written to the log of uses.

Replace value… changes the value and keeps the name and uses. Remove deletes the secret; removing an SSH key also closes the ssh-agent sockets that served it.

App-wide or one project

A terminal sees the secrets of its own project, and the app-wide ones that no project secret of the same name overrides. A project's Agentic Works database or Google Cloud service account secret does not override: an app-wide secret of the same name stays visible to that project's terminals. A project's secrets are never visible to another project's terminals, and connecto secret does not take --project: it works only for the terminal's own project.

Which programs and variables are allowed

A program given a secret can do anything with it, so the vault refuses programs that run whatever they are told: shells (sh, bash, zsh, fish, pwsh…), interpreters and runners (python, node, ruby, perl, bun, deno, npx, npm, uv, make, awk, sed, osascript…), and wrappers (env, sudo, xargs, nohup, timeout, open…). Versioned names such as python3.12 count too.

The variable cannot be one that changes how programs start or that Connecto sets: PATH, HOME, SHELL, NODE_OPTIONS, PYTHONPATH, GIT_SSH_COMMAND, EDITOR and others, or any name beginning LD_, DYLD_ or CONNECTO_.

Connecto hides the value in a program's output in every form it knows. A program that prints it in some other form can still reveal it. Allow only programs you trust with the secret, such as /opt/homebrew/bin/gh.

How agents use secrets

Every terminal has these commands. Each one is answered for the terminal that ran it, identified by Connecto from its processes, never by anything the agent says.

connecto secret list

The secrets this terminal can use: name, scope (app or project), uses (http, command, ssh…) and description. Never a value.

NAME          SCOPE    USE
GITHUB_TOKEN  app      http
              Pull requests on github.com/acme/web
DEPLOY_KEY    project  ssh
Values are never shown to terminals.

connecto secret url <NAME>

For a secret with a web use. It prints a local address, http://127.0.0.1:<port>/<token>/<NAME>/, where the token identifies this terminal. The agent sends requests under it, adding the API path:

BASE=$(connecto secret url GITHUB_TOKEN | head -1)
curl -s "${BASE}repos/acme/web/pulls"

Connecto sends the request on to the bound address plus that path, with the bound header set to the prefix and the value, and drops any header of that name the terminal sent. It follows no redirect (one to another host would take the header with it), asks for an uncompressed answer, and removes this secret's value, and the encodings listed above, from the response headers and body. Other vault values in the response are not removed here. The server you bound receives the value, so it can send it back in a form Connecto does not recognize: bind only addresses you trust with it. It listens on 127.0.0.1 only. Requests take bodies up to 32 MB, and answers up to 64 MB.

connecto secret run <NAME> -- <program> [args]

For a secret with a program use. The command resolves the program to a full path the way the terminal's shell would, and Connecto runs it only if that path (after following links) is one you allowed:

connecto secret run GH_TOKEN -- gh pr list

Connecto starts the program itself, not the terminal, in the project folder (or the folder the command was typed in, when that is inside the project). It gets no input, a short environment (PATH, HOME, USER, LOGNAME, LANG, TMPDIR, TERM=dumb) plus the value in the one variable, and at most 10 minutes. Its output and exit code come back to the terminal with this secret's value and its recognized encodings hidden. Other vault values are hidden too, but only in a stream that is valid UTF-8 text; in binary output they are left as they are. At most 1 MB of each stream is kept.

connecto secret ssh <NAME>

For an SSH key. It prints an SSH_AUTH_SOCK line and the public key:

export SSH_AUTH_SOCK='/…/connecto-vault-501/…'
ssh-ed25519 AAAA… connecto DEPLOY_KEY

The socket is an ssh-agent served by Connecto, in a folder only you can open. It serves only processes of the terminal it was made for, answers only "list keys" and "sign" (nothing can add, remove or export a key through it), and reads the key from the vault on each request, so replacing or removing the key takes effect at once. The public key is what the server's authorized_keys needs.

macOS and Linux only. On Windows SSH keys can be kept and generated, but not used to sign.

connecto secret request

An agent that needs a secret it does not have asks you for it:

connecto secret request <NAME> --reason '<why>' [--kind token|password|ssh-key]
    [--http <https://base> [--header H] [--prefix P]]
    [--command </full/path> --env VAR] [--ssh]
    [--agentic-works]
  • --reason is required: one plain sentence saying what the agent will do with the secret and where.
  • --kind is token (the default), password or ssh-key.
  • The other options propose a use: --http a web address (header Authorization and prefix Bearer  unless given); --command and --env, always together, a program and its variable; --ssh, or --kind ssh-key, an SSH key. --agentic-works asks for an Agentic Works database connection string and goes with no other use.
connecto secret request GITHUB_TOKEN \
  --reason 'Open pull requests on github.com/acme/web through the GitHub API' \
  --http https://api.github.com

The agent is told to end its turn. When you answer, it gets a [connecto notice]: that you declined, or that the secret is set and how to use it (connecto secret url GITHUB_TOKEN…). Never the value. A terminal may have three requests waiting, and twenty may wait in all; a second request for the same name from the same terminal is refused while the first waits.

What makes a reason acceptable.

Connecto checks the reason only to stop one that tells you nothing. It does not judge whether it is true. The reason is refused, and the agent is asked to write it again, when it:

  • is over 300 characters as shown (it is refused, never cut, so you see all of it);
  • has fewer than two different words (runs of letters and digits) of three characters or more that are not filler such as "needed", "token", "access", "task" or "operations" (in English or Italian);
  • has only words that are part of the secret's own name.

"Restart staging PostgreSQL" passes, and so does "Deploy to Vercel" for VERCEL_TOKEN. "deploy deploy" and "I need it for normal operations" do not. The refusal never repeats the reason, in case something was pasted into it by mistake.

The request dialog

A request opens a dialog over the window. From the top, it shows:

  • Who is asking, as Connecto knows it: the terminal's id, its kind of agent and its project, as in "Terminal claude-3 (Claude) of project web asks for a token named GITHUB_TOKEN." The terminal's tab name, which an agent may have set, is shown apart as a label Connecto has not checked.
  • What it is for: the reason, in large type, in quotes. These are the agent's own words; decline if they do not match what you asked it to do.
  • Where it will be used: one sentence for each use, saying exactly what Approve grants, such as Sent only to "https://api.github.com" (and addresses under it), by Connecto, in the header "Authorization", after "Bearer ". Each address, header, path and variable is shown in double quotes, with every character that is not plain printable ASCII written as \u{…}, so two different destinations never look alike. If what Approve grants is not what the terminal proposed (you changed it, or the form kept one of several proposed uses), the dialog says so and lists the proposal.
  • Keep it for: app-wide or the terminal's project.
  • How it may be used: the proposed use, which you can change.
  • The value: paste it. For an SSH key, Generate a new SSH key makes an Ed25519 pair and shows the public half.

Approve keeps the secret with the use shown. Decline keeps nothing. Text from the terminal (its id, name and reason) is shown on one line, with control, bidirectional and zero-width characters turned into spaces and double quotes into single ones, so it cannot break out of its quotes or pretend to be part of the dialog. A proposed program path with a line break, a control character or a space at either end is refused before it reaches the dialog.

Minimize, or Esc, folds the request into a card in the bottom-right corner, so you can read the terminal under it, where the agent often explains what it needs. Clicking the card opens it again. One request is open at a time. A new request from a terminal whose request you minimized in the last five minutes, or still have minimized, joins the stack marked new instead of covering what you are reading.

Paired Macs and remote projects

From a Mac paired with another (see Remote sessions), a remote project's secrets show in Settings → Secrets under that project, and its terminals' requests open the same dialog here.

  • That project's own secrets only. You can add, replace and remove a remote project's secrets, change their uses, and generate SSH keys, as on that Mac. Its app-wide secrets and other projects' secrets are never listed or touched from here. A request from a remote terminal can only be kept in its own project.
  • The value goes one way. It travels inside the encrypted link between the two Macs and is kept in that Mac's vault, never in this one's. Nothing sent back holds a value, and the form here is cleared once it is sent.
  • SSH keys are made there. "Generate a new SSH key on <Mac> and approve", and "Generate an SSH key on <Mac>" in Settings, ask that Mac to make and keep the key, with the SSH use set; its private half never leaves it.
  • The first answer wins. A request shows on every Mac viewing that project. Once one answers, the others' dialogs close; a late answer is refused.
  • The other Mac's person is told. Every change made from a paired Mac is listed there in a notice: what changed and in which project, never a value.
  • Pause applies. On the Mac that keeps the secrets, Pause refuses every secret action from a paired Mac, and hides its waiting requests from it.

If the other Mac runs a Connecto too old for this, the section says so and nothing can be changed from here. Nothing is ever kept in this Mac's vault in its place.

The connecto secret commands themselves work only for the terminal's own project, on its own Mac. An agent cannot reach another project's secrets with --project.

Pause

Under Pause, terminals can still list their secrets, but request, url, run and ssh are refused.

Pause does not close what a terminal was given before it: a secret url address it already has still forwards requests, and an ssh-agent socket it already has still signs. To stop further uses, set the secret's use to Not usable: the next request through the address, signature or secret run is refused. That does not undo a use already under way: a program already started keeps the value in its environment until it ends, and a web request already sent on can finish.

Removing the secret also stops further uses, but for a project secret that shares its name with an app-wide one, the terminal's existing address then reaches the app-wide secret, if that one has a web use. Setting the project secret to Not usable keeps it in the way.

What the vault does not protect against

  • Model provider keys are not vault secrets. The OpenRouter and Together AI keys for Pi, and the Together AI key for Claude through TogetherLink, are given to those terminals in their environment (OPENROUTER_API_KEY, TOGETHER_API_KEY), where the agent can read them.
  • Outside macOS, or with a data folder of its own, the master key is not protected from you. On Windows any program running as you can read Credential Manager. On Linux, and in a build started with a data folder of its own, the key is a file beside the secrets document. There, encryption keeps values out of a plain read of the file, nothing more.
  • An allowed program can leak. A program with a One program use holds the value and can print it in a form Connecto does not recognize.
  • A bound server can leak. A web use sends the value to the address you bound. Connecto removes the value and its recognized encodings from the answer, but a server that returns it in another form reveals it to the terminal. An SSH use gives the terminal signatures and the public key; Connecto does not hand it the private key.
  • The web address is a bearer token. A terminal's secret url address lasts until Connecto quits. Any process told it, such as another terminal of yours, can use that terminal's web secrets through it. Connecto does not show it the values, but the answers it gets are only as filtered as described above.
  • Remote viewing is not redacted. Paired Macs you view terminals from receive the raw output.
  • A paired Mac can direct a project's secrets. It could already type into that Mac's terminals. It can now also set where a project's secret is sent or which program gets it. The notice on the other Mac is how its person learns of it.
  • Connecto's own keys (device keys, the relay token, the Jev key) are kept as before, not in the vault (see Where secrets are kept).
  • Hiding is best effort. It catches a value and its common encodings, not every transformation a program can apply.

Agentic Works database secrets

The credentials of Agentic Works are kept in the vault as project secrets that only Connecto uses: no terminal can use them through url, run or ssh.

  • A database connection string has the Agentic Works database use. An agent asks for one with, for example: 
    connecto secret request WORKS_DB --kind password --agentic-works \
  --reason 'Link the staging PostgreSQL job queue for this project'
    See Agentic Works: secrets.
  • A Google Cloud service account key has its own use, Google Cloud service account, and is imported from Terminal → Agentic Works…, not asked for with secret request. See Google Cloud SQL.
