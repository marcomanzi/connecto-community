Updates

Connecto keeps itself up to date. A new version is downloaded in the background and installed by itself, with one restart. Your terminals come back afterwards, and agents that were in the middle of a turn carry on.

How it works

  1. A check at launch, then every minute. Connecto reads a small file, connecto.studio/downloads/update.json, that names the newest version, and fetches it again only when it changed. It sends nothing about you or your machine: the request carries only Connecto-Updater/<version> as its user agent.
  2. A download in the background. When there is a newer version, Connecto downloads it and checks it before installing it (see below). A newer one found meanwhile takes its place.
  3. Installed as soon as nothing holds it back. Connecto waits while a pairing is under way, a file is being transferred, a package is being installed, or you typed in a terminal in the last 30 seconds. The strip at the top of the window says what it is waiting for.
  4. The restart. Connecto quits, the new version is put in place, and it starts. Open projects and terminals are restored, and agent sessions resume where they were. An agent that was in the middle of a turn is told continua and carries on.
  5. Never in a loop. A version is installed by itself once at most, and Connecto does not restart by itself twice within ten minutes. A version that does not start is replaced by the one you had.

To check by hand, choose Connecto → Check for Updates… (on Windows, File → Check for Updates…), or Check now in Settings → Connecto Home → Updates. There you can also turn off Check for updates automatically, or Install updates automatically: then a strip says Connecto 0.3.11 is ready, with Update and restart and Later, and Connecto waits for running agent turns before it restarts. There is one release channel: no betas.

What is checked

  • The feed is signed. update.json carries an ed25519 signature. Connecto has the matching public key built in, so a feed changed by anyone else is refused.
  • The download matches. The feed names each file's size and SHA-256, and the download must match both.
  • On a Mac, Apple's checks too. The new app must be intact, signed with the same Developer ID as the one running, and accepted by Gatekeeper (notarized by Apple). Anything else is not installed.
  • Never older. Only a newer version than the one running is offered.

If the new version does not start

The version you had is kept until the new one has started properly. If the new one has not started within two minutes, it is moved aside, the previous version is put back and started, and a note says so. That version is not offered again; the next one is.

On a Mac the previous version is kept in Connecto's data folder (updates/previous), and an older one goes to the Trash. On Windows it is kept beside the install folder, as Connecto.previous.

Where Connecto must be installed

  • Mac: in a folder you can write to, normally Applications. A copy run straight from the disk image cannot update itself; Connecto then offers the download page instead.
  • Windows: in %LOCALAPPDATA%\Programs\Connecto (unzip the download into %LOCALAPPDATA%\Programs). A copy elsewhere installs its first update there.

The download count on the home page counts new downloads only: an update of an existing install is not counted.
