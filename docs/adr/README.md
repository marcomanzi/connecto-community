# Architecture decision records

These cover the UI relay PoC. ARCHITECTURE.md section 19 holds the earlier proposed list, whose numbers are separate. Probe IDs (R1 to R21) are in [UI-RELAY-POC.md](../poc/UI-RELAY-POC.md) section 3.

| - | - | - |

| [0002](0002-threads-no-async.md) | Threads and bounded channels, no async runtime | Accepted for this slice |
| [0003](0003-hardened-seatbelt-profile.md) | Hardened Seatbelt profile; write boundary covers indirect routes | Accepted (superseded by 0013) |
| [0004](0004-exact-device-rules.md) | Exact per-session TTY rules; agents get no new PTYs | Accepted (superseded by 0013) |
| [0005](0005-structured-ack-and-capture.md) | Claude hooks and Codex `notify` for ack and capture | Accepted for this slice, amended after T-003 |
| [0006](0006-user-click-breaks-loops.md) | Every relay hop needs a user click | Accepted for this slice (superseded by 0015 for agents) |
| [0007](0007-private-copies-from-local-binaries.md) | Private copies come from local signed binaries | Accepted for this slice |
| [0008](0008-login-outside-sandbox.md) | Login runs outside the sandbox with no agent | Accepted, amended by 0009 (superseded by 0013) |

| [0017](0017-remote-sessions.md) | Remote sessions over iroh, authorized by SSH keys, in `connecto-net` | Accepted, first slice built (no UI) |
| [0018](0018-rebrand-to-connecto.md) | Rebrand from Magneto to Connecto, and how an existing install carries over | Accepted |
| [0019](0019-plain-shell-terminals.md) | Plain shell terminals, and the terminal-kind model | Accepted |
| [0020](0020-system-config-by-default.md) | New projects use the system configuration; isolated is advanced | Accepted |
| [0021](0021-default-automations.md) | Six default automations, off, seeded once and never over the user's own | Accepted |
| [0022](0022-mutual-pairing.md) | Pairing by two codes, both ways: each machine types the other's code, names it, and saves one record | Accepted, replaces the one-sided pairing of 0017 |
| [0023](0023-send-readiness-first-send-only.md) | Readiness gates only the first send to a terminal; later sends are typed whatever the screen shows | Accepted as a known limitation; fix sized, not built |
| [0024](0024-sqlite-memory-store.md) | Project memory is one SQLite file per project, bundled SQLite with FTS5 | Accepted; Windows build not yet verified |
| [0025](0025-memory-runs-on-provider-agnostic-utility-sessions.md) | Memory runs on provider-agnostic utility sessions (Claude and Codex), in the project folder, read-only as far as each CLI allows | Accepted, extends 0001 |
| [0026](0026-open-app-scheduler.md) | The dream schedule runs only while the app is open, once per local date | Accepted |
| [0027](0027-secret-vault.md) | A vault of the person's secrets, encrypted at rest, used by terminals through bindings the app carries out (web proxy, one program, ssh-agent), and asked for by terminals through a dialog | Accepted |
| [0028](0028-voice-calls-on-device.md) | Calls in Connecto Chat use on-device speech recognition and speech around the project's agent; Foundation Models only condense replies | Accepted, first slice built |
| [0029](0029-project-task-board.md) | A project's task board is a file its app session agent keeps and Connecto Chat reads; tasks run one at a time, each as the project's prompt says | Accepted, built |
| [0030](0030-updates-install-themselves.md) | Updates are checked every minute and install themselves when nothing blocks a restart; agent turns they cut resume with "continua", once | Accepted, built; not yet tried on a real update |
| [0031](0031-project-operations.md) | Project operations are approved scripts in the project (`.connecto/ops`), run by `connecto op`, suggested on matching prompts (local match, then Jev) and intercepted only where the person opted in | Accepted |
| [0032](0032-cli-improvements.md) | CLI improvements: Settings offers tasks a coding CLI does on itself, each only with its CLI installed; "Claude auto apply insights" opens a Claude terminal on Opus in the active project that runs `/insights` and applies its suggestions, asking before anything risky | Accepted, built |
| [0033](0033-functional-memory.md) | Functional memory: `.functionalMemory/` Markdown at the repository root, updated by a read-only utility session when main advances (debounced, from the diff), written by the host and committed on its own; read by peers' voice calls through a project ask | Accepted, built |
| [0034](0034-gemini-live-calls.md) | Calls can go through Gemini Live (the person's key, in the Keychain): the phone talks to Google directly, Gemini knows the project from its functional memory and reaches the project's agent through non-blocking tools; a task starts only on the person's yes, checked by the app; proposals are paraphrased aloud in every call | Accepted, first slice built; not tried against Google or on a device |
| [0035](0035-cross-project-bridge.md) | An agent reaches another open project's terminals only with an explicit `--project` (and `connecto projects` to find them): list, read, send/ask, result, watch and unwatch, to terminals open to everyone; the caller is a stranger with a seat there, answers are forwarded home, Pause in either project refuses, both projects' audits record it | Accepted, built |
| [0036](0036-agentic-works-several-databases.md) | A project's Agentic Works links several named databases (dev, staging, production), each with its own connection and secret; work types are published once for all or some of them; one job at a time per project, every database in turn (several at once since 0039), each outcome written back to its own database; a failing database is marked and skipped | Accepted, built |
| [0037](0037-package-tool-requirements.md) | A package may declare the tools it needs (`requires`): Connecto looks for them without running anything but a version flag, installs one only in a visible shell terminal after the user confirms the exact command, gives manual steps only for anything needing a licence or sign-in, and refuses to add the package while one is missing; Game Dev (Godot only) is a second built-in package | Accepted, built |
| [0038](0038-opencode-agent.md) | OpenCode (the 1.x line) is a fifth agent: a plugin written to the run folder and named in `OPENCODE_CONFIG_CONTENT` reports Claude's hook payloads; Isolated points the three XDG folders into the project's profile (the agent's shell gets the user's back); login is OpenCode's own (`providers login`, `/connect`) and never starts a profile over; installed from opencode.ai and run in place | Accepted, built; tested with the real CLI and a stand-in model |
| [0039](0039-agentic-works-parallel-jobs.md) | A project's Agentic Works runs up to its "jobs at once" setting (1 by default, up to 32) at the same time: its linked databases share the places, the database running the fewest getting the next; each job has its own claim, journal row, folder, prepare, agent and 30 minutes; old queues lose their one-job index on first use | Accepted, built; not yet tried by hand |
| [0040](0040-agentic-works-job-questions.md) | A job's agent that hits a problem or misses information may ask the user one question at a time (`connecto works ask`) and end its turn; the question shows in a dialog over the window (project, job, type, database), the answer comes back as a `[connecto notice]` read with `connecto works answer`; the 30 minutes include the wait, questions close 5 minutes before the deadline, and a job always ends with its JSON | Accepted, built; not yet tried by hand |
| [0041](0041-agentic-works-stand-in-agents.md) | A job that asks for Antigravity (blank, `agy` or `antigravity`) runs on the first agent the project can use when Antigravity cannot run there: Codex with GPT Terra, Claude with Haiku, Pi, OpenCode (their own models); usable means installed, not signed out, active and allowed in the project's Tools; chosen per job and shown on the running job; jobs naming another agent are unchanged | Accepted, built; not yet tried by hand |
| [0042](0042-project-clone-and-delete.md) | New Project can clone a repository (the system's git; https, ssh, git, local only; into a private staging folder, published without replacing anything); Delete Project closes the project, stops everything, and moves its folder to the Trash only (never for good), refusing links, volume roots, system and Connecto folders and folders holding other projects, bound to the confirmed directory's identity | Accepted, built; real Trash and Windows not exercised |
| [0043](0043-end-of-task-status-recap.md) | Every agent in a project with the built-in package ends a task that changed something with a four-point recap (Done / Committed-pushed / Not done / Waiting on user): Claude from `.claude/rules`, the others at launch from text compiled into Connecto (Pi, OpenCode, Antigravity by their instruction options, Codex through its `SessionStart` hook); the project's AGENTS.md and CLAUDE.md are never written; Codex without hooks gets none | Accepted, built; checked with the real CLIs, not through a rebuilt Connecto |
| [0044](0044-project-tools-set.md) | A project uses any set of one or more coding CLIs (checkboxes): saved as `tools` (one or `all`, what older builds read) plus the exact `tool_list`; enforced where every terminal is added or started (the registry and the pane), read from the saved settings each time, so nothing starts a CLI the project leaves out; callers pick an allowed CLI or say why; hidden utility sessions (titles, Functional Memory) are exempt | Accepted, built; not yet tried by hand |
| [0045](0045-agent-roster-and-second-opinion.md) | `connecto agents [--roles]` lists each coding CLI as ready, unverified, unusable, checking or not allowed (the Tools check `add` uses; ready as a job's agent is decided, read only: a project's Pi host is never started, Antigravity is at most unverified, Claude through TogetherLink shows its provider) and picks coder (Claude first), reviewer (Codex first, another CLI than the coder's) and second opinion (another CLI than the asker's), marked "same CLI" when none other is ready, with Opus, Astra and `gemini-4-neon-<effort>`; the coordinator fills the effort by a four-line rubric; the team skills use it, and a user-invoked `second-opinion` skill is added (package version 10) | Accepted, built; not yet tried through a rebuilt Connecto |
| [0046](0046-bridge-text-adds-to-user-instructions.md) | The bridge text adds to the user's own instructions on Codex and Pi instead of replacing them: Codex gets it from Connecto's `SessionStart` hook (text in the Codex process's environment, hook context limit raised so it is not cut), never `-c developer_instructions`; Pi gets it as a `connecto-bridge` prompt section from Connecto's extension, never `--append-system-prompt`, so `APPEND_SYSTEM.md` stays (Pi 0.85, without sections, gets them appended to its resolved prompt); new and resumed sessions, a resume skipping the message only when the thread's latest one from Connecto is byte-identical (otherwise handed over as replacing earlier ones); threads started before this change keep their old behaviour; preflight turns the bridge off with a reason when the stored helper would not hand the text over or Codex's hooks feature is off | Accepted, built; checked with the real Codex 0.167 and Pi 1.5.2 and 0.85.1, not through a rebuilt Connecto |
